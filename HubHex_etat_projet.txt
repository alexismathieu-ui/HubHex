QU'EST-CE QUE HUBHEX ?
  Plateforme web type mini-GitHub interne : depots heberges sur HubHex, Kanban,
  fichiers + editeur Monaco, communaute, differentiation (stack, journal, templates,
  graphe). Monorepo Next.js 16 (front TS strict) + Express 5 (back JS) + PostgreSQL.

DEMARRAGE LOCAL
  Terminal 1 : cd backend && npm run dev     → http://localhost:4000
  Terminal 2 : cd frontend && npm run dev    → http://localhost:3000
  Page accueil : http://localhost:3000/  (visiteur non connecte)
  Inscription : /inscription  |  Connexion : /connexion
  Checklist : docs/CHECKLIST_DEMARRAGE_LOCAL.md

AUTH (important — change recemment)
  - Access JWT court : JWT_ACCESS_EXPIRES_IN=15m (defaut)
  - Refresh token 7 j : table refresh_tokens, hash SHA-256 en BDD
  - Routes : POST /api/auth/login, /refresh, /logout
  - Front : localStorage hubhex_token + hubhex_refresh ; renouvellement auto ~14 min
  - cookie-parser + cookie HttpOnly hubhex_refresh sur path /api/auth
  - Revocation refresh : logout, changement MDP, reset MDP, suppression compte
  - Explorateur + editeur : authFetch (frontend/src/lib/auth/authFetch.ts) — retry auto
        si 401 ACCESS_TOKEN_EXPIRED (DepotFileExplorer, DepotCodeWorkbench)

1. VISION ET ARCHITECTURE
================================================================================

HubHex = plateforme de gestion de projets dev (soutenance), type mini-GitHub interne :
chaque depot est heberge sur HubHex (pas un lien GitHub externe), chemin public type :
  username/slug-du-depot

Stack :
  - Frontend : Next.js 16 (App Router), React 19, TypeScript strict, Tailwind 4, Monaco
  - Backend  : Express 5, Node.js (JavaScript) — port 4000
  - BDD      : PostgreSQL (schema au boot via ensureDatabaseSchema())
  - Auth     : JWT access court (15m) + refresh token (7j, BDD + cookie HttpOnly)

Monorepo :
  HubHex/
    backend/          API Express (JS) + scripts
    frontend/         Application Next.js (.ts / .tsx, strict)
    database/         hubhex_schema.sql + .gitignore dump (backend/database/)
    docs/             Documentation + guides prof / securite
    postman/          Collection tests API
    http/             hubhex.http (REST Client, inclut refresh/logout)
    README.md
    HubHex_plan_complet.txt
    HubHex_etat_projet.txt (ce fichier)

Depot GitHub : https://github.com/alexismathieu-ui/HubHex

3. CONFIGURATION .env BACKEND (rappel)
================================================================================

Obligatoire :
  DATABASE_URL=postgresql://...
  JWT_SECRET=32+ caracteres aleatoires
  FRONTEND_URL=http://localhost:3000

Recommande dev :
  ENABLE_RATE_LIMIT=false
  ALLOW_DEV_RESET_TOKEN=false
  HOST=0.0.0.0
  JWT_ACCESS_EXPIRES_IN=15m
  JWT_REFRESH_EXPIRES_DAYS=7

Optionnel :
  PUBLIC_API_URL=https://xxx.trycloudflare.com  (apres npm run share)
  SMTP_* pour reset password par email

Pour audit cyber avec rate limits :
  ENABLE_RATE_LIMIT=true  puis redemarrer l'API
